# 3. OPERATION SCAFFOLD ARCHITECTURE — Template Structure

## What Is an Operation Scaffold?

An Operation Scaffold is a structured template injected into a subagent's context when they receive a delegated task. It tells the agent exactly what to do and how to do it.

## Scaffold Structure

```
┌─────────────────────────────────────────┐
│         OPERATION SCAFFOLD              │
├─────────────────────────────────────────┤
│ 1. OPERATION TYPE: [e.g., CONTENT-01]   │
│ 2. DEPARTMENT: [e.g., Content]          │
│ 3. PRIMARY AGENT: [e.g., Scribe]        │
│ 4. SUPPORT AGENTS: [e.g., Proof, Radar] │
│ 5. REQUIRED INPUTS: [what I need]       │
│ 6. STEP SEQUENCE: [ordered workflow]    │
│ 7. TOOL CHAIN: [tools in order]         │
│ 8. DELIVERABLES: [exact outputs]        │
│ 9. QUALITY GATE: [acceptance criteria]  │
│ 10. HANDOFF PROTOCOL: [what to return]  │
│ 11. TRUST CATEGORY: [which trust score] │  ← NEW
│ 12. EXPRESS LANES: [direct handoffs]    │  ← NEW
│ 13. PROACTIVE TRIGGERS: [self-init OK?] │  ← NEW
└─────────────────────────────────────────┘
```

Items 11-13 are new additions from the Agency Expansion Framework, connecting each scaffold to the trust/autonomy system.

## Scaffold Injection Protocol

When Felix delegates a task, the prompt includes:

```
=== OPERATION SCAFFOLD ===
Operation: [EXEC-01, ENG-03, CONTENT-01, etc.]
Department: [Executive, Engineering, Content, etc.]
You are: [Persona name and role]
Your trust level for this work: [score] → [autonomy level]

CONTEXT:
[User's original request]

YOUR MISSION:
[Specific task for this agent]

STEP SEQUENCE:
1. [Step 1]
2. [Step 2]
...

TOOL CHAIN:
[Ordered list of tools to use]

DELIVERABLES EXPECTED:
- [Deliverable 1]
- [Deliverable 2]
...

QUALITY STANDARDS:
[Standards for this department]

EXPRESS LANES AVAILABLE:
[Direct handoffs this agent can make without Felix relay]

HANDOFF INSTRUCTIONS:
When complete, return to Felix with:
- Summary of what was done
- List of files created (with Google Drive links)
- Any issues or items needing attention
- Recommendations or next steps
=========================
```

- Track outcomes (track_outcome)

### 21.1 — Nine Evaluators Unimplemented

# 22. TIER 1: EVALUATOR ACTIVATION PLAN

**Goal:** Activate all 9 unimplemented evaluators to establish full visibility.

**This tier is PREREQUISITE for Tiers 2-6.**

## Activation Priority

| Priority | Evaluator | Why First |
|---|---|---|
| 1 | `daily_spend` | Foundation for cost control |
| 2 | `agent_spend_ratio` | Prevents resource monopolization |
| 3 | `tool_boundary_violations` | Essential for trust score tracking |
| 4 | `content_pipeline` | Essential for earned autonomy (Scribe/Proof) |
| 5 | `purpose_drift` | Safety net for proactive initiative |
| 6 | `desk_queue` | Workload-aware routing |
| 7 | `pii_exposure` | Expanding external communication autonomy |
| 8 | `failover_rate` | Operational resilience |
| 9 | `auth_failures` | Security hardening |

## Implementation Specifications

**daily_spend:** Hook into all LLM API calls. Track input + output tokens per request. Calculate cost using model-specific pricing. Maintain running daily total. Expose: `spend_percent`, `spend_total`, `spend_by_agent`.

**agent_spend_ratio:** Depends on daily_spend. Calculate each agent's % of daily total. Track 1-hour and 24-hour rolling ratios. Expose: `agent_percent_of_total`, `top_spender`, `top_spender_percent`.

**tool_boundary_violations:** Track which agent attempted which unauthorized tool, how many times, over what period. Expose: `unauthorized_tool_attempts` (count per agent per 24h), `attempted_tools`, `agent_id`.

**content_pipeline:** Track content lifecycle: created_by → reviewed_by → approved_by → published_by. Flag bypassed reviews. Expose: `unreviewed_content`, `bypassed_reviews`, `review_turnaround_hours`.

**purpose_drift:** After each response, classify task topic vs. agent's focus areas using lightweight LLM. Track on_topic vs. off_topic over 48-hour window. Felix and Blueprint exempt. Expose: `off_topic_ratio`, `off_topic_examples`, `agent_id`.

**desk_queue:** Query each agent's desk for pending count, oldest task age, growth rate. Expose: `queue_depth`, `oldest_pending_hours`, `queue_growth_rate`.

**pii_exposure:** Regex patterns for email, phone, SSN, credit card. Context-aware (internal vs. external). Whitelist known business addresses. Expose: `pii_in_output`, `pii_types`, `pii_context`.

**failover_rate:** Track primary model attempts/successes/failovers over 1-hour window. Expose: `failover_percent`, `primary_model`, `failover_targets`.

**auth_failures:** Monitor all auth events (API keys, OAuth, sessions). Track by source/type. Expose: `failed_attempts`, `failure_sources`, `failure_types`.

---

## 27.2 — Protocol Flows

**Specialist + Critique:** Felix → delegate_task(specialist) → result → critique_response(result) → if ≥ 7/10 deliver, else revise.

**Chain of Debates:** Felix → debate(question, 4 participants) → multi-perspective synthesis → deliver with consensus level.

**Tree of Thought:** Felix → tree_of_thought(question, 3 branches) → score each → select/synthesize best → deliver.

**Full Council:** ToT (3 approaches) → Debate (multi-perspective on best) → Critique (quality check) → estimate_cost (resources) → deliver.

# 28. NEW GOVERNANCE RULES

Nine new rules to support the Agency Expansion framework:

### Rule #32: trust-score-update
**Priority:** 7/10 | **Category:** COMPLIANCE
Recalculate trust scores on task completion, quality review, or governance event. Apply autonomy level changes with hysteresis (upgrades: 5 days sustained; downgrades: immediate).

### Rule #33: trust-score-critical-drop
**Priority:** 9/10 | **Category:** SECURITY
When any trust score drops below 25: restrict all autonomy, escalate to human.

### Rule #34: proactive-action-budget-enforcement
**Priority:** 7/10 | **Category:** RESOURCE_MANAGEMENT
Block proactive actions exceeding daily PAB. Reset at midnight tenant timezone.

### Rule #35: proactive-action-quality-monitor
**Priority:** 6/10 | **Category:** PERFORMANCE
If >50% of proactive actions are Unnecessary/Harmful over 7 days: suspend proactive rights, -10 trust, 7-day suspension.

### Rule #36: express-lane-health-monitor
**Priority:** 6/10 | **Category:** OPERATIONS
3 consecutive express lane failures: suspend lane, route through Felix.

### Rule #37: express-lane-volume-cap
**Priority:** 5/10 | **Category:** RESOURCE_MANAGEMENT
Daily cap of 10 handoffs per express lane. Overflow routes through Felix.

### Rule #38: environmental-signal-escalation
**Priority:** 8/10 | **Category:** OPERATIONS
URGENT signals: notify Felix. CRITICAL signals: notify Felix + human.

### Rule #39: collective-intelligence-budget
**Priority:** 6/10 | **Category:** COST_CONTROL
Daily caps: Debate (5), ToT (5), Full Council (2). If budget ≥ 80%: critique only.

### Rule #40: earned-autonomy-audit
**Priority:** 4/10 | **Category:** COMPLIANCE
Weekly Monday audit: trust changes, autonomy transitions, proactive actions, express lane usage.
